# RISK_REGISTER

Severity = impact × likelihood. Every risk names an owner (which phase) and a mitigation that is
already reflected in the plan, not a hope.

| # | Risk | Sev | Impact | Mitigation | Phase |
| --- | --- | --- | --- | --- | --- |
| R-01 | **Scope collapse into a demo.** 14 agents + 3D studio + two renderers is a multi-month build; pressure to ship something visible produces a dashboard that fakes work. | High | The product becomes worthless exactly as specified ("not a simulated dashboard"). | Vertical slices only. Phase 1 gate requires a real job with a real state transition and a real cancel. Studio built only after events exist (Phase 3). No component ships before its data exists. | all |
| R-02 | **Flaky test baseline.** Donor run showed `test_current_artifact_is_reused_without_quarantine` failing once then passing 3/3 in isolation; full suite then green. | Med | A red suite hides real regressions; a green suite is not trusted. | Run the suite 3× in CI before a phase gate. Any test that fails once is quarantined with an issue, never silently retried. | 1 |
| R-03 | **Provider capability drift.** A model that worked yesterday stops supporting `response_format`, and the failure surfaces as unparseable JSON deep in a stage. | High | Jobs fail at random with misleading errors. | Capabilities are declared by the operator, validated pre-call, and a `CapabilityMismatch` is a `BLOCKED` with the exact missing capability. A daily health probe records the model the endpoint actually echoed, not what was configured. | 1, 4 |
| R-04 | **Credential leakage.** A key reaches a log line, an error body, a job artifact, or a browser response. | Critical | Key rotation, possible billing damage. | Sentinels in tests: a fake key with a unique string is planted and every artifact/response/log is grepped for it. Error bodies redacted before surfacing. `has_credential` only. DPAPI for at-rest. | 1 |
| R-05 | **SSRF through the provider editor.** Editable `base_url` + server-side credential = request forgery with auth attached. Measured donor gap. | Critical | Metadata endpoints, internal admin panels, or a redirect to an attacker host. | `netguard` with CIDR deny list, resolve-then-pin, no redirects, explicit `allow_private_hosts` opt-in, origin-bound credentials. | 1 |
| R-06 | **Render nondeterminism.** Frames differ between runs; per-scene rerender produces visible seams. | Med | Rerenders look different; QA can't compare. | Seeded PRNG per `(job, scene, element)`; bundled fonts; identical encoder settings for concat; frame-hash comparison test. | 2 |
| R-07 | **Bang Motion cannot do 9:16 well.** Starters are 16:9; the vertical recipe is a paragraph in a reference doc, not tested code. | High | The secondary renderer is unusable for Shorts and the motion-skill plan is half empty. | Ingest step renders one starter at 1080×1920 and inspects it *before* committing to the integration. If it fails, the skill is marked `vertical: unsupported` and only Remotion is used for Shorts — an honest limitation, reported as such. | 2 |
| R-08 | **GPU contention.** 6 GB VRAM shared by Remotion's Chrome, the 3D studio, and the dashboard. | Med | Render crashes or the studio freezes the machine. | Render concurrency = 1; studio pauses on `RENDERING` + low free VRAM; DPR and shadow tiers; `frameloop="demand"` when hidden. | 3 |
| R-09 | **YouTube quota and policy.** 10 000 units/day default, ~100 `videos.insert`/day, and API-uploaded videos from unaudited projects can be restricted. | Med | Publishing fails late, after the expensive part. | Cadence default 2/week (far under quota); private-first always; public is a separate confirmed action; quota usage shown in the UI; no scheduled task can bypass approval. | 4 |
| R-10 | **Resume duplicates paid calls.** A crash after a paid completion but before the artifact write re-runs the model. | High | Silent cost, and inconsistent artifacts. | Completion marker written last; draft persisted before revision; resume test asserts a provider call counter of exactly 1 across a simulated crash. | 1 |
| R-11 | **Two trees diverge.** Donor keeps evolving in OneDrive while this repo ports modules. | Med | Ported fixes get lost; effort duplicated. | Port by module with the donor's tests; record the donor commit for each ported module in `docs/PORT_LOG.md`; donor is frozen for the duration (no new work there except critical fixes, which are ported forward). | all |
| R-12 | **The 3D studio becomes the product.** Time goes into clay materials while the pipeline is unfinished. | High | Prettiest possible non-functional app. | Phase 3 starts only after Phase 2's exit gate. Studio is a projection; no studio work can unblock a pipeline task. | 3 |
| R-13 | **Model-generated content reaches privileged code.** A scene field is interpolated into a shell command or an HTML template. | Critical | Arbitrary code execution on the operator's machine. | `SceneSpec` validation before any renderer; no `shell=True`; argv arrays; generated HTML only in an isolated browser process with no network and a staging-only filesystem. | 2 |
| R-14 | **Text-only model claimed to have "seen" frames.** | High | QA passes broken video; operator trust destroyed. | `vision` is a declared capability; absent → `skipped_no_vision_provider`, visible and non-passing. | 2 |
| R-15 | **Disk growth.** 18 donor jobs = 122 MB. Renders plus frame sequences multiply this. | Low | Disk pressure on a 113 GB free volume. | Frame sequences deleted after encode unless `--keep-frames`; retention policy on `data/jobs`; size shown in Settings. | 2 |
| R-16 | **Windows-specific traps.** Port collisions where a bind "succeeds" on an occupied port; MSYS path translation; `NODE_ENV=production` pruning devDependencies. | Med | Hours lost to failures that look like code bugs. | Explicit `--port` everywhere with a connect+exclusive-bind probe; native absolute paths for native tools; `npm install --include=dev`. Documented in `docs/DEV_NOTES.md`. | 1 |
| R-17 | **Remotion licensing.** Free for individuals and ≤3-person orgs; larger orgs need a paid licence. | Low | Legal exposure if the operator scales. | Recorded in `THIRD_PARTY.md` with the exact eligibility wording and a re-check trigger (hiring). | 1 |
| R-18 | **Silent mock.** A live run falls back to mock and produces a publishable-looking artifact. | Critical | Fabricated content published. | `provider_mode` recorded at job creation; mock jobs are `publishable: false` at the approval gate; the router raises `NoProviderAvailable` instead of degrading in live mode. | 1 |

## Assumption log

| # | Assumption | If wrong |
| --- | --- | --- |
| A-1 | The operator runs one worker at a time. | Leases already support multi-worker; a second worker process is a Phase 4 addition, not a rewrite. |
| A-2 | A local OpenAI-compatible endpoint (9router on :20128, or Ollama) is available for live runs. | Mock mode still exercises the whole pipeline; only quality of output changes. |
| A-3 | Edge TTS network access is available. | Narration fails at the audio stage with a clear error; a local TTS provider can be added behind the same interface. |
| A-4 | The RTX 3050's 6 GB is enough for one 1080×1920 Remotion render. | Proven by the donor (79.8 s render). If a heavier template appears, concurrency stays 1 and quality drops. |
| A-5 | The donor tree remains readable for porting. | Modules are ported with their tests; a ported module is then independent. |
